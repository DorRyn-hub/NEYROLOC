# Правила работы с проектом

- Основной корень — этот репозиторий; активное desktop-приложение находится в `NEYROLOCK_5`.
- Общаться с владельцем по-русски. Сохранять существующие изменения; сначала читать действующие инструкции и исходники.
- Перед каждой новой работой выполнять `git fetch origin --tags` и проверять `git status`, `git log --oneline --decorate -10`, `git rev-list --left-right --count HEAD...origin/main`. Рабочая ветка исходников — `main`.
- Если локальная ветка отстаёт и рабочее дерево чистое, выполнять `git pull --ff-only origin main`. При расхождении истории сначала сохранить локальные изменения и согласовать объединение; никогда не затирать изменения владельца.
- После каждого завершённого изменения выполнять подходящие проверки, проверку безопасности полного индекса, отдельный коммит и обычный push в `main`. Эти коммиты и push разрешены владельцем заранее.
- Если проверки обнаруживают существующие ошибки, отличать их от ошибок изменения и сообщать конкретный результат. Не заявлять о прохождении непройденных проверок.
- Использовать настроенную Git-идентичность владельца; не добавлять служебную атрибуцию, соавторов или подписи инструментов. Проверять сообщения, метаданные и публикуемые файлы до отправки.
- Если push не удался, явно сообщать, какие коммиты и изменения остались только локально. Незавершённая отправка не считается сохранением на GitHub.
- Запрещены force push, удаление опубликованных веток/тегов и переписывание опубликованных коммитов. Восстановление выполнять новым коммитом через workflow согласно `VERSIONING.md`.
- Не публиковать секреты, персональные данные, реальные конфиги, базы, логи, окружения, сборки и приватные резервные копии. Не обходить hooks и не добавлять игнорируемые файлы принудительно.
- Вложенный локальный `NEYROLOC/.git` сохраняется отдельно. В этом репозитории iOS-файлы хранятся обычными исходниками; не заменять их gitlink/submodule при `git add`.
- Ветка `version-control` — постоянный центр восстановления и default branch GitHub. Не использовать её для обычных изменений приложения. При изменениях инструментов восстановления обновлять её отдельным обычным коммитом и push после проверок.
- Область обычного сохранения — исходники и история. Развёртывание, публикация сайта и изменение production требуют отдельного задания.
