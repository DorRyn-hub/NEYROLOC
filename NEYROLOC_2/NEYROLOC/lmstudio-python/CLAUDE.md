## Project Overview

The LM Studio Python SDK (`lmstudio-python`) is a Python client library for communicating with LM Studio's native websocket API. The SDK provides both synchronous and asynchronous APIs for interacting with LM Studio's LLM and embedding models.

Key architectural aspects:
- **Dual API design**: The SDK provides both `sync_api.py` and `async_api.py` with parallel implementations
- **Websocket communication**: Uses `httpx-ws` to communicate with LM Studio via websocket (not the OpenAI compatibility layer)
- **Schema generation**: Data models in `src/lmstudio/_sdk_models/` are auto-generated from `lmstudio-js` JSON schemas
- **Plugin system**: Supports creating Python plugins for LM Studio (tools, prompt preprocessors, token generators)

## Development Commands

### Testing

```bash
# Run tests on default Python version (3.12)
tox -m test

# Run tests on specific Python versions
tox -e py3.10  # oldest supported
tox -e py3.14  # latest supported
tox -m test_all  # all versions

tox -m test -- tests/test_basics.py

tox -m test -- -m "not slow"  # skip slow tests
tox -m test -- -m "not lmstudio"  # skip tests requiring LM Studio

# Load/unload test models (requires LM Studio running)
tox -e load-test-models
tox -e unload-test-models
```

## Architecture and Code Structure

### API Layer Organization

The SDK is organized into several layers:

1. **`src/lmstudio/_sdk_models/`**: Auto-generated data models (DO NOT EDIT - regenerate via `tox -e sync-sdk-schema`)
2. **`src/lmstudio/json_api.py`**: Core base classes and abstractions shared between sync/async APIs
3. **`src/lmstudio/sync_api.py`**: Synchronous client API (uses async websocket in background thread)
4. **`src/lmstudio/async_api.py`**: Asynchronous client API (native async/await)
5. **`src/lmstudio/history.py`**: Chat history management and file handling
6. **`src/lmstudio/schemas.py`**: Schema utilities and structured response support
7. **`src/lmstudio/sdk_api.py`**: Public API decorators and error classes

### Client Architecture

- **`Client` (sync) / `AsyncClient` (async)**: Main entry point, manages websocket connections
- **Session types**: Each API namespace (LLM, embedding, system, etc.) has a dedicated session type
- **Endpoint types**: Each API channel endpoint has a dedicated base type to avoid code duplication
- **`SessionData` pattern**: Rich result objects that can call back into the SDK (e.g., model listings that can load models)

### Test Suite Organization

Tests use a specific naming convention:
- `tests/test_*.py`: Mixed async/sync tests or tests not amenable to auto-conversion
- `tests/async/test_*_async.py`: Async tests (method names end in `_async`)
- `tests/sync/test_*_sync.py`: Auto-generated sync versions (generated by `tests/async2sync.py`)

Convert async tests to sync: `python tests/async2sync.py`

### Plugin System

Located in `src/lmstudio/plugin/`:
- Plugin hooks: tools provider, prompt preprocessor, token generator
- Development runner available via `python -m lmstudio.plugin`
- Examples in `examples/plugins/`

## Development Guidelines

### Adding New API Support

- Each new API namespace should get a dedicated session type
- Each new channel endpoint should get a dedicated base endpoint type
- Use `json_api.SessionData` for rich result objects that offer methods calling back into the SDK

### Code Style

- **Autoformatting**: Use `ruff` for formatting (run `tox -e format`)
- **Linting**: All `ruff` warnings must be fixed (avoid `# noqa` comments)
- **Type checking**: Uses `mypy` in strict mode - must pass cleanly
- **Docstrings**: Google-style docstrings required (except in tests and magic methods)
- **Python version**: Requires Python 3.10+ (uses pattern matching)

### Testing Requirements

- Test suite requires LM Studio running locally on port 1234
- Specific models must be loaded for tests to pass (see `tests/README.md`)
- Mark slow tests (>1-3 seconds) with `@pytest.mark.slow`
- Tests use pytest markers: `slow`, `lmstudio`, `wip`

## Communication and Contribution

- **Before contributing**: Comment on existing issues or open a new one - the team discourages drive-by PRs
- **CLA required**: All contributors must sign a Contributor License Agreement
- **Small PRs**: Keep PRs focused on one concern for faster review
- **Documentation**: Maintained separately in the [docs repo](https://github.com/lmstudio-ai/docs)

## Submodules

The repository includes `lmstudio-js` as a submodule for schema generation:

```bash
git submodule update --init --recursive
```

This is required to run `tox -e sync-sdk-schema`.
