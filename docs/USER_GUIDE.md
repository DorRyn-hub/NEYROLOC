<a id="mode"></a>
## 1. Где будет работать модель

| Режим | Что вам нужно | Куда отправляется текст |
| --- | --- | --- |
| Local GGUF | `llama-cpp-python`, файл `.gguf`, достаточно памяти | Генерация выполняется на компьютере |
| OpenAI | Собственный API-ключ, интернет, доступная вашему аккаунту модель | В API выбранного провайдера |
| Groq | Собственный API-ключ, интернет, поддерживаемая модель | В API Groq |
| Телефон через браузер | Работающий NEYROLOC на компьютере и подключение к нему | На компьютер, затем в выбранный им backend |

Backend — способ подключения к модели. Файл модели и программа NEYROLOC —
разные вещи: установка интерфейса не добавляет нейросеть автоматически.

Для первой локальной попытки выполните [оба шага установки модели](INSTALL.md#local-model).
Для облачного режима скачивать GGUF не требуется.

<a id="first-message"></a>
## 2. Первый диалог — проверка по шагам

1. Слева выберите **Local GGUF**, **OpenAI** или **Groq**.
2. Заполните параметры подключения. Для локального режима укажите настоящий
   файл `.gguf`; для облачного — свой API-ключ.
3. Нажмите **Подключить**. Дождитесь получения списка моделей.
4. В поле **Модель** выберите нужную модель. Если имя уже отображается, но ввод
   сообщения недоступен, откройте список и подтвердите выбор. Для введённого
   вручную имени нажмите Enter.
5. Дождитесь сообщения в нижней строке **Модель готова: …**.
6. Внизу справа введите короткий запрос, например:

   > Привет! Ответь по-русски двумя предложениями: что ты умеешь?

7. Нажмите **Отправить**.
8. Дождитесь непустого ответа. Первый запрос может быть медленнее последующих.
9. Для прекращения длинного ответа нажмите **Стоп** и дождитесь остановки.

![Главное окно с пустым профилем](images/desktop-first-launch.png)

Если кнопка отправки недоступна, модель ещё не подготовлена либо возникла ошибка.
Если появился только ваш вопрос, а ответ пустой, работа генерации ещё не подтверждена:
смотрите [разбор проблем](TROUBLESHOOTING.md).

Первую проверку делайте короткой. Большие документы и длинные переписки добавляйте
после успешного ответа на простой вопрос. Маленькая тестовая модель может ошибаться,
плохо соблюдать инструкции и отвечать медленно на слабом компьютере.

<a id="models"></a>
## 3. Скачать, выбрать и сменить модель

### Через библиотеку

Откройте **Инструменты → Библиотека моделей…** либо кнопку
**Открыть библиотеку моделей** в боковой панели.

- **Скачанные** — файлы, доступные библиотеке приложения. **Обновить** перечитывает
  список, **Использовать** выбирает выделенную модель.
- **Рекомендованные** — встроенный каталог. Выделите строку и нажмите
  **Скачать выбранную**. Размеры в каталоге ориентировочные.
- **Поиск HuggingFace** — поиск репозиториев и файлов моделей.

Для начала подойдёт небольшая текстовая Instruct-модель из группы **Тестовые**.
После скачивания выберите её на вкладке **Скачанные**. Если установлен локальный
backend, приложение может сразу начать подготовку выбранного файла.

### Поиск на Hugging Face

1. Откройте вкладку **Поиск HuggingFace**.
2. Введите название интересующей модели и нажмите **Искать модели**.
3. Выберите репозиторий или заполните поле Repo ID известным идентификатором
   вида `автор/название-репозитория`.
4. Нажмите **Искать файлы**.
5. Выберите подходящий `.gguf`, затем **Скачать**.
6. Дождитесь завершения; перейдите в **Скачанные**, обновите список и используйте файл.

Для открытых файлов HF-токен обычно не нужен. Закрытая или gated-модель может
потребовать аккаунт, принятие условий автора модели и собственный токен чтения.
Токен Hugging Face не является ключом OpenAI или Groq. Не вставляйте его в чужой
репозиторий и не публикуйте в обращениях поддержки.

Перед скачиванием прочитайте описание, лицензию и требования на странице модели.
Встроенная рекомендация не отменяет лицензию автора и не гарантирует совместимость.
Для первого опыта выбирайте один цельный текстовый GGUF, избегая разбитых частей,
мультимодальных комплектов и файлов огромного размера.

### Что означают обозначения

| Обозначение | Практический смысл |
| --- | --- |
| `.gguf` | Формат модели для локального backend |
| Instruct / Chat | Модель обучена отвечать в диалоге |
| 0.5B, 1B, 3B, 7B | Примерный масштаб количества параметров |
| Q4, Q5, Q8 | Вариант квантования; влияет на размер и качество |
| Context / n_ctx | Объём текста, который модель может учитывать |

Большая модель не гарантирует лучший результат в каждой задаче. Начните с той,
которая стабильно помещается в память. Увеличивайте размер после проверки.

### Смена модели

Остановите ответ и сохраните важный чат. Выберите другой файл или модель,
при изменении параметров нажмите **Подключить**, подтвердите выбор модели и
дождитесь готовности. Для независимого разговора нажмите **Новый**.

<a id="cloud"></a>
## 4. OpenAI и Groq — собственный облачный доступ

Облачные запросы используют ваш аккаунт провайдера. NEYROLOC не выдаёт общий
API-ключ и не оплачивает запросы. Лимиты, доступность в вашем регионе, поддерживаемые
модели и стоимость смотрите в кабинете провайдера перед использованием.

### OpenAI

1. Изучите [официальный API quickstart](https://developers.openai.com/api/docs/quickstart).
2. В своём аккаунте создайте API-ключ на [странице API keys](https://platform.openai.com/api-keys).
3. Скопируйте ключ для личного использования; не отправляйте его автору приложения.
4. В NEYROLOC выберите **OpenAI** и вставьте ключ в поле **API-ключ**.
5. При использовании официального OpenAI поле **Base URL** оставьте пустым.
6. Нажмите **Подключить**, выберите доступную вашему аккаунту модель и подтвердите её.
7. Отправьте короткий тестовый запрос.

Ключ нужен именно в форме приложения: текущий backend проверяет это поле.
Одна лишь переменная окружения с ключом не заменяет заполнение формы.

### Groq

1. Откройте [официальный quickstart Groq](https://console.groq.com/docs/quickstart).
2. В своём кабинете создайте API-ключ.
3. В NEYROLOC выберите **Groq**, заполните поле ключа и нажмите **Подключить**.
4. Выберите актуальную модель из тех, которые поддерживает ваш аккаунт.
5. Подтвердите модель и проверьте коротким сообщением.

Подписи внутри старого интерфейса не являются обещанием бесплатного доступа.
Условия провайдера могут измениться; ориентируйтесь на свой кабинет.

### Совместимый API другого сервиса

Backend OpenAI позволяет задать **Base URL**. Это дополнительный вариант для
людей, которые уже знают адрес и правила своего OpenAI-совместимого сервера.
Используйте адрес API из его документации и ключ этого сервера. Не отправляйте
ключ одного провайдера неизвестному другому серверу.

Совместимость зависит от реализации сервера: приложение вызывает streaming
Chat Completions и передаёт температуру. Не каждая модель поддерживает эти параметры.
Поддержка отдельного API не означает поддержку всех его моделей и функций.

### Почему список моделей ещё не доказывает подключение

При неудачном запросе списка текущий код некоторых облачных backend'ов может
показать запасные названия моделей. Они могут устареть. Доказательство работы —
успешный непустой ответ, а не наличие строк в выпадающем списке.

Ошибки 401/403 относятся к ключу или доступу, 429 — к лимитам/квоте;
404 может означать недоступную модель либо неправильный адрес API.
Подробности находятся в [помощи](TROUBLESHOOTING.md).

<a id="settings"></a>
## 5. Настройки ответа

### Температура

Ползунок **Температура** меняет разнообразие генерации. Для последовательных
ответов начните примерно с 0.2–0.5; для свободных формулировок можно попробовать
около 0.7. Это экспериментальные ориентиры, а не гарантия правильности.

Низкая температура не превращает модель в проверенный справочник. Некоторые
облачные модели ограничивают этот параметр или не поддерживают его.

### Системный промпт

В поле **Системный промпт** можно написать общую инструкцию, например:

> Отвечай по-русски. Объясняй простыми словами. Если не знаешь ответа, скажи об этом.

Не помещайте сюда пароли и ключи. В облачном режиме инструкции также передаются
провайдеру. Модель может не выполнить инструкцию полностью.

### Контекст и GPU для Local GGUF

- Для первой небольшой модели начните с `n_ctx = 2048`.
- При CPU-сборке задайте **Слоёв на GPU** = `0`.
- При подходящей GPU-сборке можно попробовать `-1`, если модель помещается в память.
- Чем длиннее контекст, тем больше расход памяти.
- После изменения параметров снова подключите backend и подготовьте модель.

Если закончилась память, уменьшайте контекст и размер модели. Простое увеличение
чисел не улучшает качество автоматически.

<a id="chats"></a>
## 6. Как сохранить, открыть и начать чат

### Сохранить

Нажмите **Сохранить** слева или **Файл → Сохранить чат…**. Выберите свою папку
и понятное имя JSON-файла, например `разговор-2026-10-11.json`.
Проверьте, что файл появился. Сохраните его перед закрытием или обновлением программы.

Не полагайтесь на автоматическое сохранение каждого диалога: в текущем интерфейсе
надёжный пользовательский шаг — явная команда сохранения.

### Открыть

Нажмите **Открыть** или **Файл → Открыть чат…**, выберите ранее сохранённый
JSON-чат приложения. Затем подключите нужный backend и модель, если это ещё не сделано.
Файл переписки не включает в себя модель и её Python-библиотеки.

### Начать заново

Сначала сохраните нужную переписку, затем нажмите **Новый** или
**Файл → Новый чат**. Новая тема удобнее в отдельном чате: предыдущие сообщения
не будут мешать задаче и занимать контекст.

Экспорт чата может содержать весь введённый текст и ответы. Храните его как личный
документ; не прикладывайте без просмотра в публичные Issues.

<a id="phone"></a>
## 7. Как открыть приложение с телефона

Самый простой предусмотренный путь — браузер телефона в той же доверенной Wi-Fi-сети.
На телефоне ничего компилировать не нужно. Модель продолжает работать на компьютере.

### Перед подключением

- NEYROLOC установлен и открыт на компьютере.
- Backend и модель выбраны; короткий запрос на компьютере уже успешно работает.
- Компьютер и телефон подключены к одной локальной сети.
- Компьютер не спит и не отключён от сети.
- Вы используете свою доверенную сеть, а не общедоступный Wi-Fi.

### Шаги

1. На компьютере выберите **Инструменты → Удалённый доступ с телефона…**.
2. Нажмите **Включить доступ**, если сервер выключен.
3. Убедитесь, что появилось состояние **Сервер работает — телефон может подключаться**.
4. Используйте адрес блока **В этой Wi-Fi-сети** или его QR-код.
5. На телефоне откройте QR камерой либо введите показанный адрес в Safari/Chrome.
6. Если страница просит код сопряжения, введите код из окна на компьютере.
   QR-ссылка может уже содержать его.
7. Отправьте короткое сообщение с телефона и убедитесь, что ответ непустой.
8. По завершении на компьютере нажмите **Выключить доступ**.

Не вводите `localhost` на телефоне: это адрес самого телефона. Используйте LAN-адрес,
который показан на компьютере. Обычно сервер использует порт `8765`.
QR и код дают доступ к вашему приложению — не публикуйте их.

### Если телефон не открывает страницу

Проверьте [раздел помощи по телефону](TROUBLESHOOTING.md#phone).
Гостевые сети и изоляция клиентов роутером могут запрещать связь между устройствами.
Брандмауэр компьютера может потребовать разрешение входящих соединений для Python
в вашей частной сети. Не выключайте весь брандмауэр ради проверки.

### Значок на домашнем экране

После успешного открытия страницы можно добавить закладку/ярлык:

- iPhone/iPad: Safari → **Поделиться** → **На экран «Домой»**, если пункт доступен.
- Android: меню браузера → **Добавить на главный экран**, если пункт доступен.

Названия зависят от браузера. Такой значок не делает модель автономной на телефоне.
Для работы всё равно нужен включённый компьютер. Локальная HTTP-страница может
не предлагать полноценную установку PWA и офлайн-режим.

### Доступ из другой сети и мобильные сборки

В интерфейсе есть опция интернет-туннеля, но для неё нужны отдельные компоненты
и работающая инфраструктура. Эта инструкция не обещает их доступность и не включает
публикацию вашего компьютера в интернете. Для первого запуска оставьте эту опцию выключенной.
Не настраивайте проброс порта локального HTTP-сервера на весь интернет по этой инструкции.

В репозитории есть исходники Android- и iOS-обёрток, но проверенных актуальных
пользовательских APK, App Store/TestFlight-релиза в этой поставке нет.
Обычному пользователю удобнее начать с браузера. Физическое подключение телефона
в рамках подготовки этой документации не проверялось.

<a id="privacy"></a>
## 8. Где лежат ваши данные

| Данные | Где искать |
| --- | --- |
| Настройки приложения | `~/.neyrolock_5/config.json` |
| Скачанные приложением модели | `~/.neyrolock_models` |
| Кеш Hugging Face | `~/.cache/huggingface` |
| Экспортированные чаты | В папке, выбранной при сохранении |

`~` означает домашнюю папку вашего пользователя; на Windows это обычно `%USERPROFILE%`.
Настройки и модели расположены отдельно от папки с исходниками.

**API-ключи в текущей версии сохраняются в обычном JSON-файле настроек, без шифрования.**
Не отправляйте `config.json`, домашнюю папку приложения или архив личного профиля в публичный репозиторий.
Для общего компьютера используйте отдельную учётную запись ОС и контролируйте доступ к файлам.

При локальной генерации текст обрабатывается локальной моделью. Скачивание моделей
и поиск файлов требуют сетевых запросов. В облачном режиме текст переписки и
инструкции отправляются выбранному API. При телефонном доступе данные передаются
по вашей сети; локальный сервер использует HTTP. Это не механизм защищённого
обмена через недоверенную сеть.

Если случайно опубликовали ключ, отзовите его в кабинете провайдера и создайте новый.
Удаление сообщения само по себе не отменяет уже раскрытый ключ.

<a id="faq"></a>
## 9. Короткие ответы

**Можно без аккаунта GitHub?** Да: публичный ZIP скачивается без регистрации.

**Можно без облачного аккаунта?** Да: используйте Local GGUF и открытую модель.

**Нужен ли интернет после установки?** Для локальной генерации уже скачанной модели
обычно нет; для поиска, скачивания и облачных API он нужен.

**Можно только на телефоне без компьютера?** Описанный браузерный режим требует компьютера.

**Почему не хватает просто распаковать ZIP?** ZIP содержит исходники; Python,
библиотеки и выбранная модель устанавливаются отдельно.

**Есть ли гарантированный ответ на любой вопрос?** Нет. Модели ошибаются, а маленькие
модели имеют заметные ограничения. Проверяйте значимые факты самостоятельно.

**Куда писать об ошибке?** В [Issues](https://github.com/DorRyn-hub/NEYROLOC/issues)
по [шаблону безопасного обращения](TROUBLESHOOTING.md#support).
