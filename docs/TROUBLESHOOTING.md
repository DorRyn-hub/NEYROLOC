# NEYROLOC: решение проблем

[Главная](../README.md) · [Установка](INSTALL.md) · [Как пользоваться](USER_GUIDE.md)

Сначала найдите свою ошибку в таблице. Выполняйте команды для своей ОС и из папки
с `main.py`. Не меняйте системные настройки наугад и не запускайте неизвестные
«исправляющие» скрипты из комментариев.

<a id="python-not-found"></a>
## 1. Python не найден

### Windows

Закройте старый PowerShell после установки Python, откройте новый и выполните:

```powershell
py -3.14 --version
python --version
```

Если первая команда работает, используйте `py -3.14` при создании окружения.
Если работает только вторая, проверьте версию и создавайте окружение через неё.

Если `python` открывает Microsoft Store, команда может указывать на системный
алиас вместо установленного интерпретатора. Проверьте установку Python и алиасы
в параметрах Windows; начните с [официальной инструкции](https://docs.python.org/3/using/windows.html).
Команда `py install 3.14` относится к современному Python install manager;
старый launcher её не понимает.

### macOS / Linux

Проверьте:

```sh
python3 --version
```

На macOS после установки ветки 3.14 также попробуйте `python3.14 --version`.
Если нужная команда существует, используйте её в шаге создания `.venv`.
На Linux установите Python и пакет venv способом вашего дистрибутива.
Не заменяйте системный интерпретатор ОС вручную.

<a id="folder"></a>
## 2. Не найдены файлы или окружение

`can't open file main.py` означает, что запускается команда из неправильной папки
либо архив ещё не распакован. Откройте корень, где рядом видны `main.py` и `NEYROLOCK_5`.
Если распаковщик создал два вложенных каталога, войдите во внутренний.

**Windows:**

```powershell
Get-Location
Test-Path .\main.py
Test-Path .\NEYROLOCK_5\requirements.txt
Test-Path .\.venv\Scripts\python.exe
```

**macOS / Linux:**

```sh
pwd
ls main.py NEYROLOCK_5/requirements.txt
ls .venv/bin/python
```

Первые два файла входят в ZIP, `.venv` создаётся вами. Если её нет, вернитесь
к шагу создания окружения в [установке](INSTALL.md). Если перенесли папку,
создайте окружение заново: старые пути внутри `.venv` могут перестать работать.

`START_NEYROLOC_NEW.command` и старые упаковочные скрипты предназначались для
локальной структуры разработчика. Для новой установки используйте команды
из руководства, а не старые абсолютные пути.

<a id="dependencies"></a>
## 3. Не установлены библиотеки

`ModuleNotFoundError: No module named 'PySide6'` и похожие сообщения означают,
что пакет отсутствует в Python, которым запущено приложение. Используйте именно
интерпретатор проекта и `-m pip`, чтобы установка и запуск относились к одной среде.

**Windows:**

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\NEYROLOCK_5\requirements.txt
.\.venv\Scripts\python.exe -c "import PySide6; print('Qt: OK')"
.\.venv\Scripts\python.exe .\main.py
```

**macOS / Linux:**

```sh
./.venv/bin/python -m pip install -r NEYROLOCK_5/requirements.txt
./.venv/bin/python -c "import PySide6; print('Qt: OK')"
./.venv/bin/python main.py
```

Не используйте случайный глобальный `pip`. Для ошибки `externally-managed-environment`
создайте `.venv`; не обходите защиту системного Python ради этого приложения.
Ошибка прав доступа — повод проверить папку и окружение, а не запускать `sudo pip`.

Если pip сообщает об отсутствии совместимого пакета, проверьте версию Python,
ОС и архитектуру. Ориентируйтесь на официально поддерживаемые платформы зависимости.
Обновление pip выполняйте внутри `.venv`.

<a id="llama-install"></a>
## 4. llama_cpp отсутствует или не устанавливается

Основной `requirements.txt` не устанавливает `llama-cpp-python` автоматически.
Поэтому интерфейс может открываться, а **Local GGUF** оставаться недоступным.
Выполните [дополнительную установку](INSTALL.md#local-model), затем перезапустите приложение.

### No matching distribution / отсутствует wheel

У `llama-cpp-python` есть разные пакеты для сочетаний ОС, архитектуры, Python и
ускорителя. Команда с `--only-binary=llama-cpp-python` специально прекращает
установку, если готового пакета нет.

1. Проверьте, какой Python используется.
2. Откройте [официальную инструкцию библиотеки](https://github.com/abetlen/llama-cpp-python#installation).
3. Выберите версию Python, для которой есть нужный готовый wheel, и создайте
   **новое** окружение с этим интерпретатором; заново установите остальные зависимости.
4. Либо выполните сборку из исходников с подходящим компилятором.

Для некоторых готовых GPU wheels upstream указывает Python 3.10–3.12. Проверяйте
условия конкретного индекса; поддержка пакетом нового Python не означает наличие
каждого варианта готового GPU wheel.

### CMake / compiler / Failed building wheel

Если убрать `--only-binary`, pip может начать компиляцию. Для неё нужны инструменты:

- Windows: подходящие C/C++ build tools по инструкции библиотеки.
- macOS: Xcode Command Line Tools; для Metal правильный актуальный флаг — `GGML_METAL`.
- Linux: C/C++ compiler и инструменты сборки вашего дистрибутива.

Если не хотите настраивать компилятор, начните с совместимого CPU wheel или облачного
режима. Не устанавливайте случайные готовые DLL из сторонних обсуждений.

### Ошибка архитектуры на Mac

Проверьте архитектуру своего Python:

```sh
./.venv/bin/python -c "import platform; print(platform.machine())"
```

На Apple Silicon для нативной установки обычно ожидается `arm64`; Intel-сборка
под Rosetta — другой вариант среды. Не смешивайте бинарные библиотеки разных
архитектур в одной `.venv`. Пересоздайте среду с выбранным интерпретатором.

### Ошибки CUDA / Metal / shared library

Сначала подтвердите запуск маленькой модели на CPU со слоями GPU `0`.
Если CPU работает, а GPU нет, проверяйте конкретный ускоритель, драйвер и сборку
по upstream-инструкции. Установка стандартного пакета не гарантирует GPU-ускорения.

<a id="linux-qt"></a>
## 5. Linux: Qt, xcb, libGL и отсутствие окна

PySide6 содержит Qt, но графическая платформа всё ещё использует системные
библиотеки и рабочий стол Linux. Запуск по SSH без графической сессии не равен
запуску на обычном desktop-компьютере.

Сначала запустите из терминала внутри графического рабочего стола и прочитайте
точное имя отсутствующей библиотеки. Для диагностики плагинов:

```sh
QT_DEBUG_PLUGINS=1 ./.venv/bin/python main.py
```

Вывод может быть длинным. Найдите сообщения `cannot open shared object file`
или конкретную отсутствующую библиотеку. На Ubuntu/Debian, если отсутствует именно
`libxcb-cursor.so.0`, пример установки соответствующего пакета:

```sh
sudo apt install libxcb-cursor0
```

Остальные пакеты выбирайте по фактической ошибке и своему дистрибутиву, сверяясь
с [официальными требованиями Qt на Linux](https://doc.qt.io/qt-6/linux-requirements.html).
Не копируйте библиотеки от другого дистрибутива в системные каталоги.

<a id="download"></a>
## 6. Модель или зависимости не скачиваются

### Сеть, сертификаты, прокси

Проверьте, открывается ли официальный сайт в браузере и достаточно ли места на диске.
Убедитесь, что дата и время системы верны. В организации доступ может ограничивать
прокси или фильтр. Следуйте правилам вашей сети и документации используемого Python.
Не отключайте проверку TLS-сертификатов как универсальное решение.

### Hugging Face: 401 / 403 / gated

Файл может требовать аккаунт, разрешение владельца модели и принятие её лицензии.
Получите доступ на странице модели, используйте собственный HF-токен чтения либо
выберите открытую модель. Облачный API-ключ не заменяет HF-токен.

### 404 / EntryNotFound / файл отсутствует

Встроенный каталог мог устареть или автор переименовал файл. Откройте страницу
репозитория модели, проверьте Repo ID, точное имя файла и формат `.gguf`.
На вкладке поиска перечитайте доступные файлы. Не переименовывайте `.safetensors`
в `.gguf`: это не конвертация.

### Файл скачан, но не появился

Нажмите **Обновить** на вкладке **Скачанные**. Проверьте, завершился ли прогресс.
Если файл находится в вашей отдельной папке, укажите его через **Обзор** в
настройках Local GGUF. Не удаляйте кеш и непонятные частичные файлы без проверки,
особенно если его используют другие программы.

<a id="memory"></a>
## 7. Модель не загружается или заканчивается память

- Попробуйте небольшую текстовую модель 0.5B–1B.
- Уменьшите контекст до `2048` или меньшего поддерживаемого значения.
- Для первой CPU-проверки поставьте слои GPU `0`.
- Закройте тяжёлые приложения и убедитесь, что есть свободная память.
- Перезапустите NEYROLOC после неудачной загрузки и повторите короткий тест.

Расход RAM/VRAM больше размера файла. Контекст тоже занимает память.
`Killed`, `out of memory`, ошибка выделения памяти и внезапное закрытие могут
указывать на нехватку ресурсов, но окончательную причину устанавливайте по журналу ошибки.

Сообщение `unsupported architecture`, неверная magic/signature или ошибка чтения
GGUF могут означать неподдерживаемую модель, неполный файл либо другую структуру.
Проверьте исходную страницу и размер скачивания. Для первого теста используйте
цельный текстовый GGUF, а не набор мультимодальных или split-файлов.

<a id="generation"></a>
## 8. Отправка недоступна, ответы пустые или медленные

### Кнопка неактивна

Выбор backend → параметры → **Подключить** → подтверждение модели → ожидание
**Модель готова**. Одного видимого названия модели может быть недостаточно:
выберите его в списке или подтвердите введённое имя Enter.

### Ответ пустой / ошибка после отправки

Сохраните нужный чат, попробуйте новый чат и один короткий вопрос.
Проверьте статус внизу окна и ошибку в терминале. Для облачного режима проверьте
доступность модели, ключ и поддержку streaming Chat Completions. Для локального —
попробуйте небольшую совместимую Instruct-модель.

Если воспроизводится на корректных настройках, это может быть ошибка приложения;
отправьте [обращение](#support). Не считайте пустой ответ успешной проверкой.

### Очень медленно

Маленькая модель, короткий контекст и короткий запрос помогают отделить проблему
ресурсов от других причин. CPU без ускорения может генерировать медленно.
Проверьте, соответствует ли GPU-настройка установленной сборке. Длинная история
увеличивает объём обработки; попробуйте новый чат.

### Неправильный язык или странные ответы

Добавьте просьбу отвечать по-русски в системный промпт. Попробуйте другую
текстовую Instruct-модель. Маленькая модель и сильное квантование могут давать
слабые ответы; изменение температуры не устраняет все ошибки.

<a id="cloud"></a>
## 9. Облачный API

| Ошибка | Что проверить |
| --- | --- |
| 401 | Правильный ключ именно этого провайдера, отсутствие случайных пробелов, не отозван ли ключ |
| 403 | Разрешения аккаунта, проекта, модели и доступность сервиса |
| 404 | Точное имя действующей модели и Base URL |
| 429 | Квоту, лимиты частоты и состояние аккаунта в кабинете провайдера |
| Timeout / connection error | Интернет, адрес API, прокси, состояние сервиса |
| Unsupported parameter | Совместимость модели с параметрами текущего приложения |

Для официального OpenAI оставьте Base URL пустым. Для другого сервера используйте
его документированный API-адрес. У Groq адрес задаёт сам backend.

Запасной список моделей не подтверждает правильность ключа: текущий код может
показывать его при ошибке получения реального списка. Выбирайте актуальную
поддерживаемую модель. Не публикуйте тело запроса с ключом или личным текстом.

<a id="phone"></a>
## 10. Телефон не подключается

1. Сначала проверьте успешный ответ на самом компьютере.
2. Откройте диалог удалённого доступа и проверьте, что доступ включён.
3. Подключите телефон к тому же Wi-Fi; мобильный интернет сам по себе не даёт
   доступ к локальному адресу компьютера.
4. Используйте свежий адрес из диалога: IP может поменяться после смены сети.
5. Не используйте на телефоне `localhost` / `127.0.0.1`.
6. Проверьте, что сеть не гостевая и роутер не изолирует клиентов.
7. Если ОС запрашивает разрешение Python на входящие соединения, разрешайте
   нужную частную сеть согласно настройкам вашей ОС.
8. Проверьте, что компьютер не уснул и приложение не закрыто.

`Connection refused` часто означает выключенный сервер или неправильный порт;
тайм-аут — недоступность адреса, изоляцию сети или фильтрацию соединения.
Если порт `8765` занят другой программой, завершите только известную вам
конфликтующую программу либо сообщите об ошибке; не останавливайте процессы наугад.

Если страница открылась, но требует код, используйте текущий код из приложения.
Не публикуйте QR, адрес с кодом и снимок окна сопряжения.

Наличие интернет-туннеля в интерфейсе не доказывает готовность его внешней
инфраструктуры. Внешний доступ не является частью этой пользовательской установки.

<a id="limitations"></a>
## 11. Известные ограничения и уровень проверки

- Пока опубликованы исходники, готовых установщиков для обычного пользователя нет.
- Проверено открытие текущего GUI и библиотеки моделей на macOS с Python 3.14,
  с изолированным пустым профилем. Иллюстрации получены из этого запуска.
- Это не проверка новой установки на Windows/Linux, всех GPU, реальных облачных
  запросов или подключения физического телефона.
- Часть существующего тестового набора приложения не проходит: во время настройки
  сохранения версия дала 22 failures и 34 errors при 64 тестах. Часть тестов
  рассчитана на другой уровень реализации. Исправление приложения — отдельная работа.
- Проверки безопасности репозитория и восстановления истории проверяют сохранение
  исходников; они не подтверждают работоспособность каждой функции приложения.
- Встроенные каталоги облачных и локальных моделей могут устаревать.
- Наличие мультимодальной модели в каталоге не означает проверенную обработку
  изображений в текущем интерфейсе. Руководство описывает текстовый чат.
- API-ключи сохраняются в обычном файле настроек без шифрования.
- Внешний туннель и мобильные исходники требуют отдельных компонентов/сборок.

При сообщении об ошибке укажите версию исходников и воспроизводимые шаги.
Не описывайте непроверенную функцию как гарантированно рабочую.

<a id="support"></a>
## 12. Как попросить помощь и не раскрыть личные данные

Создайте [Issue в репозитории](https://github.com/DorRyn-hub/NEYROLOC/issues/new).
Для этого нужен аккаунт GitHub. Issue в публичном репозитории видят другие люди.

Скопируйте и заполните шаблон:

```text
Заголовок: кратко, что не работает

ОС и версия:
Архитектура компьютера (Intel/AMD x64 / Apple Silicon / другая):
Python --version:
Версия исходников (тег / SHA / дата скачивания ZIP):
Способ установки (ZIP / Git):
Режим (Local GGUF / OpenAI / Groq / телефон):
Имя модели, без ключей и личного текста:

Что делал по шагам:
1.
2.
3.

Ожидал:
Получилось:
Точный текст ошибки после удаления личных данных:
Какие шаги из инструкции уже проверил:
```

Для Git-установки версию можно получить командой `git rev-parse --short HEAD`.
Для ZIP достаточно указать тег или дату и ветку скачивания, если SHA неизвестен.

Перед публикацией перечитайте текст и скриншоты. Уберите:

- API-ключи, токены, коды сопряжения и QR.
- Файл `config.json`, cookies, заголовки Authorization и переменные окружения с секретами.
- Личные сообщения и содержимое экспортированных чатов.
- Имя пользователя в пути, адреса, телефоны, платёжные данные и другую личную информацию.

Оставьте название ошибки, безопасные имена модулей/моделей и шаги воспроизведения.
Большой приватный архив проекта для диагностики не нужен.
